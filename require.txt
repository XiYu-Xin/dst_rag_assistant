为游戏《饥荒：联机版》构建一个文字版RAG助手（DST_RAG_Assistant)。
1、项目概述
为游戏《饥荒：联机版》构建一个基于 RAG（检索增强生成）技术的智能问答助手。
用户用自然语言提问游戏相关问题，系统从灰机Wiki知识库中检索相关信息，
结合大语言模型生成准确、有据可查的回答。

2、技术栈总览
| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 语言 | Python 3.10+ | 生态成熟，AI/ML库丰富 |
| 爬虫 | requests + BeautifulSoup4 + lxml | 轻量高效的HTML抓取解析 |
| 数据处理 | Pandas + tiktoken | 结构化处理 + token计数 |
| 文本分块 | LangChain TextSplitter 或自实现 | 支持语义分块和重叠 |
| Embedding | sentence-transformers (all-MiniLM-L6-v2) | 384维，轻量高效 |
| 向量数据库 | FAISS (IndexIVFPQ) | Meta开源，支持GPU加速 |
| 关键词检索 | rank-bm25 | 纯Python实现的BM25 |
| 重排序 | CrossEncoder (ms-marco-MiniLM-L-6-v2) | 精排提升召回质量 |
| LLM | DeepSeek-V3 (API) | 性价比高，中文能力强 |
| API服务 | FastAPI + uvicorn | 高性能异步Web框架 |
| 前端 | Streamlit / Gradio | 快速搭建交互界面 |
| 配置管理 | python-dotenv + YAML | 环境变量 + 配置文件 |
| 日志 | loguru | 更友好的日志输出 |

3、核心模块与技术选型
A. 数据获取 (Scraper)
目标：获取《饥荒：联机版》的Wiki数据。
数据源：
灰机Wiki: BASE_URL = "https://dontstarve.huijiwiki.com/api.php"
实现：
可使用requests和BeautifulSoup编写爬虫，抓取指定分类（如生物、物品、机制）信息，从首页开始深度优先。
优先检查Wiki是否提供API接口（如Fandom的API），这比直接解析HTML更高效、稳定。

B.数据处理 (Processor)
目标：将原始网页转换为结构化数据，并切分成适合检索的文本块。
实现：
1.解析 (Parsing)：从HTML中提取标题、正文等核心内容，转换为干净的JSON格式。
2.切分 (Chunking)：可以按照WiKi中已有的分类体系进行划分。如：行为、环境、实体、玩家、世界、生物、巨兽、物品、食物等。保留适当的重叠部分，避免关键信息被切断。

C. 检索模块 (Retriever)
目标：根据用户问题，从知识库中快速找到最相关的信息片段。
实现：
1.嵌入 (Embedding)：使用文本嵌入模型将文本块和用户问题转换为向量。使用轻量级的 all-MiniLM-L6-v2 模型。
2.向量数据库：存储所有文本块的向量，并支持相似度搜索。FAISS。使用IndexIVF 做近似搜索
检索策略：
1.纯向量检索：将用户问题向量化，在向量库中搜索最相似的k个文本块。
2.混合检索 (Hybrid Search)：结合向量检索（语义理解）和关键词检索（BM25）（精确匹配）。
3.重排序 (Reranking)：对初步检索到的结果进行二次精细排序，将最相关的信息排在前面。

D. 问答生成 (LLM/AI)
目标：基于提问和检索到的信息，生成准确、有用的回答。
实现：
1.构造提示词 (Prompt)：将用户问题和检索到的上下文信息整合成一个清晰的提示词，要求LLM基于提供的信息回答。
2.调用LLM API：选用模型Deep Seek V4 Flash

E.交互界面（frontend）
目标：为用户提供交互界面，提供输入问题，输出回答的窗口。
实现：
聊天，用户输入问题→ 统一查询处理 → 混合检索 → 意图重排序 → 大模型总结 → 流式输出
